# Parity with pymatgen, py4DSTEM and pyxem / diffsims / orix

A checklist of what DiffractoKit holds against the documented public API of the Python packages it is the Mac-native
counterpart of, so that "complete" is a measured claim (suite ROADMAP, "Kits", phase 4). Started 2026-10-15 for 0.1.0
(`main` at 3a83d95); updated at every tag. The rows slice 1b holds were updated at bc99fa0 (ships at 0.1.1). It claims only what a test in this repository checks. A row is a Python
function or a small group of them, not every method of the class.

## What the three states mean

- **held**: a kit symbol computes the same quantity as the Python function, and a test in this repository compares the
  kit with that package's output (a committed pin generated by the pinned package) within the stated tolerance.
- **partly**: the kit computes the same or an equivalent quantity but (a) only a subset of what the function does, or
  (b) the check is against an independent truth (a closed form, a 60-digit decimal, a NumPy evaluation of the written
  definition, the suite apps' compiled code), not against this package's own output, or (c) there is no comparison at all
  yet. The "How checked" column says which; read it before relying on a row.
- **not held**: no kit symbol. "planned" names the place where it is registered or intended; it is not a promise of a date.

Numerics are held to the tolerance the Python package's own tests use; readers, I/O, indices and metadata are exact. Agreement with a package is agreement, not truth (`CLAUDE.md`); where the kit and a package differ by design the difference
is named. Counts are of rows.
