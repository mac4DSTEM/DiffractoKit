# Parity with pymatgen, py4DSTEM and pyxem / diffsims / orix

A checklist of what DiffractoKit holds against the documented public API of the Python packages it is the Mac-native
counterpart of, so that "complete" is a measured claim (suite ROADMAP, "Kits", phase 4). Started 2026-10-15 for 0.1.0
(`main` at 3a83d95); updated at every tag. The rows slice 1b holds were updated at bc99fa0 (ships at 0.1.1). It claims only what a test in this repository checks. A row is a Python
function or a small group of them, not every method of the class.

## What the three states mean

- **held**: a kit symbol computes the same quantity as the Python function, and a test in this repository compares the
  kit with that package's output (a committed pin generated by the pinned package) within the stated tolerance.
- **partly**: the kit computes the same or an equivalent quantity but (a) only a subset of what the function does, or
  (b) the check is against an independent truth (a closed form, a 60-digit decimal, a NumPy evaluation of the written
  definition, the suite apps' compiled code), not against this package's own output, or (c) there is no comparison at all
  yet. The "How checked" column says which; read it before relying on a row.
- **not held**: no kit symbol. "planned" names the place where it is registered or intended; it is not a promise of a date.

Numerics are held to the tolerance the Python package's own tests use; readers, I/O, indices and metadata are exact. Agreement with a package is agreement, not truth (`CLAUDE.md`); where the kit and a package differ by design the difference
is named. Counts are of rows.


The tables in sections 1 to 3 were rewritten on 2026-10-21 (kit audit, step 1) by walking the public API of each package from the
source on disk (`refs/`), one row per function or option group. Kit symbols were checked against `Sources/` at the audited commit
(uncommitted work in the tree is not counted). Columns:

- **Plan**: `study` = on the owner's path (the TEM study and the two apps' open kit asks: phase matching and maps, ACOM, ring and
  ellipse calibration, CIF import and symmetry, structure factors and kinematic patterns, zone axes, IPF and orientation
  symmetry, and the DiffractoKit items of the suite ROADMAP, section 4); `useful`; or `not planned (reason)`.
- **Upstream tolerance (test file)**: orix rows quote the tolerance the orix test of that function uses, with the file under
  `orix/tests/` (`np.allclose` defaults are rtol 1e-5, atol 1e-8). pymatgen and py4DSTEM ship no tests: the cell says so and
  names the tolerance arguments of the function itself where there are any. D17: `assert_allclose` defaults (rtol 1e-7).
- **[S]** (none left since 0.9.1): the kit's pinned tolerance was stricter than upstream's (D17: never stricter). The 33 rows that carried it
  were loosened to the upstream tolerance in 0.9.1; the tolerance columns and "How checked" cells state the new pins, and the
  measured values stay in brackets. **[L]**: looser, with the reason (upstream computes in float32).

A row's state is the kit's against that package's own output; a quantity checked only against an independent
truth, the apps' code or a closed form is "partly". pyxem and diffsims are not on disk, so their rows are documentation-level
and are counted apart.
